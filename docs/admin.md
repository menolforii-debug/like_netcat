# Админ‑панель

Админ‑панель доступна по `public_html/admin.php` и использует собственный роутер (`AdminRouter`).
Запросы POST защищены CSRF‑токеном. При отсутствии пользователей создаётся `admin` с случайным паролем
и выводится на странице логина.

## Роли

- `admin` — полный доступ.
- `editor` — доступ только к объектам (создание/редактирование/публикация/удаление и т.д.).

Дополнительно на уровне инфоблока можно задать права через `extra_json.permissions`.
Если права не заданы, используется дефолт: `guest` может `view`, `editor` — полный набор действий.

## Основные разделы админки

### Сайты и разделы

- Управление деревом разделов и сайтами (корневой раздел).
- Настройки сайта: домен, зеркала, включённость, HTML‑страница «сайт отключен».
- Выбор макета по умолчанию и визуальных настроек (см. ниже).

### Компоненты и шаблоны

- Компоненты описывают структуру данных (`fields_json`).
- Для каждого компонента создаются представления (`component_views`) с шаблонами list/single и системными настройками (`system_tpl`).
- Админка пишет файлы в `templates/component/<keyword>/` и хранит бэкапы.
- Создание нового компонента открывается в правой колонке экрана «Компоненты».

### Врезки

- Врезки — небольшие фрагменты HTML/JS/PHP, которые можно вставлять в макеты и компоненты через `insert_snip('keyword')`.
- Редактируются в разделе `Врезки`, содержимое хранится в базе данных и вставляется без экранирования.

### Справка

- Раздел `Справка` показывает список файлов документации.
- При клике по названию документа файл загружается в правой колонке.
- Документы рендерятся из Markdown в HTML прямо на странице (клиентский рендеринг без внешних библиотек).

### Инфоблоки

- Экземпляры компонентов в разделе.
- Указываются шаблон (`view_template`), настройки (`settings_json`) и обёртки (`extra_json`).

#### Настройки (JSON) для инфоблока

Поле **«Настройки (JSON)»** — это произвольные параметры для конкретного инфоблока.
Они сохраняются в `infoblocks.settings_json` и передаются в шаблон компонента как массив `$settings`.
Встроенных «обязательных» ключей нет — вы сами определяете, какие параметры использовать в шаблоне.

Ниже пример JSON, в котором показаны **все возможные типы значений**, которые удобно использовать
в шаблонах:

```json
{
  "title": "Заголовок блока",
  "subtitle": "Подзаголовок",
  "limit": 12,
  "offset": 0,
  "show_more": true,
  "layout": "grid",
  "css_class": "news-grid",
  "cta": {
    "text": "Смотреть все",
    "url": "/news/"
  },
  "filters": {
    "status": "published",
    "tag": "promo"
  },
  "order": [
    {"field": "published_at", "direction": "desc"},
    {"field": "title", "direction": "asc"}
  ],
  "ids": [1, 2, 3],
  "feature_flags": {
    "show_date": true,
    "show_image": false
  },
  "params": {
    "custom_key_1": "value",
    "custom_key_2": 123
  }
}
```

Пример использования в шаблоне компонента:

```php
<?php if (!empty($settings['title'])): ?>
  <h2><?= htmlspecialchars((string) $settings['title'], ENT_QUOTES, 'UTF-8') ?></h2>
<?php endif; ?>
<?php if (!empty($settings['show_more']) && !empty($settings['cta']['url'])): ?>
  <a href="<?= htmlspecialchars((string) $settings['cta']['url'], ENT_QUOTES, 'UTF-8') ?>">
    <?= htmlspecialchars((string) ($settings['cta']['text'] ?? 'Подробнее'), ENT_QUOTES, 'UTF-8') ?>
  </a>
<?php endif; ?>
```

### Объекты (контент)

- Создание/редактирование по схеме компонентов.
- Поддерживаются статусы `draft` и `published`.
- Предпросмотр публикуемых объектов доступен только для авторизованного пользователя и использует `preview_token`.

### Макеты и визуальные поля

- Макеты хранятся в `templates/layouts/`.
- Для макета есть отдельный шаблон навигации `<layout>.nav.php`.
- При создании нового макета админка подставляет дефолтные шаблоны из `templates/layouts/default/layout.tpl.php` и `templates/layouts/default/nav.tpl.php`.
- Визуальные поля (`visual_fields`) задают параметры для дизайна.
- Значения хранятся в `sections.extra_json.visual_settings` и наследуются по дереву.

### Пользователи и роли

- Создание/удаление пользователей, смена пароля и роли.

### SQL‑консоль

- Раздел `SQL` позволяет выполнять запросы и хранит историю последних команд.
- Доступен только администраторам.

### Файловый менеджер

- Раздел `Файлы` открывает Filegator внутри админки и показывает хедер админ‑панели.
- Доступен только администраторам, используется авторизация CMS.
- Корень файлового менеджера — корень проекта (на уровень выше `public_html`).
- Входной URL: `/admin.php?action=filemanager` (страница с хедером админки).
- Встроенный iframe использует `/filemanager_embed.php`, доступен только администраторам.
- Файловый менеджер берётся из `app/vendor/filegator/index.php` и реализует базовые операции: просмотр, загрузка, создание файлов и папок, удаление (через модальное подтверждение), переименование (через модальное окно), редактирование файлов.
- Редактирование выполняется в модальном окне с CodeMirror: при клике «Редактировать» страница открывается с параметром `edit`, а модалка автоматически показывается. После сохранения выполняется редирект на список без `edit`, чтобы модалка не открывалась повторно. Режим подсветки определяется функцией `detectEditorMode()` по расширению файла, стили CodeMirror подключаются через CDN, и редактор обновляется при показе модального окна.
- Удаление и переименование выполняются через модальные окна, клик вне окна не закрывает модал; переименование доступно для файлов и папок.
- Список файлов сортируется по клику на заголовки колонок; сортировка по умолчанию — по размеру (папки сверху).
- Кнопки действий в таблице отображаются иконками с подсказками.
- В «Свойствах» можно посмотреть параметры файла/папки и изменить права доступа (chmod).
- Кнопка «Редактировать» доступна только для типовых файлов проекта (php/html/css/js/json/yml/md/txt и т.п.).
- Навигация дополнена кликабельными хлебными крошками.
- При создании или загрузке файлов/папок, если имя уже существует, менеджер добавляет уникальный суффикс, чтобы избежать перезаписи.

### Логи

- Админ‑лог показывает действия пользователей (фильтры по сущности, действию, пользователю).

## Загрузка файлов

- Поля компонентов типа `file` сохраняются в `public_html/files/component/<infoblock_id>/`.
- Файлы визуальных настроек — в `public_html/files/layouts/<layout>/<field_id>/`.
- Проверяются расширения и MIME‑типы (список в `app/admin/AdminHelpers.php`).
