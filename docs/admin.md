# Админ‑панель

Админ‑панель доступна по `public_html/admin.php` и использует собственный роутер (`AdminRouter`).
Запросы POST защищены CSRF‑токеном. При отсутствии пользователей создаётся `admin` с случайным паролем
и выводится на странице логина.

## Роли

- `admin` — полный доступ.
- `editor` — доступ только к объектам (создание/редактирование/публикация/удаление и т.д.).

Дополнительно на уровне инфоблока можно задать права через `extra_json.permissions`.
Если права не заданы, используется дефолт: `guest` может `view`, `editor` — полный набор действий.

## Основные разделы админки

### Сайты и разделы

- Управление деревом разделов и сайтами (корневой раздел).
- Настройки сайта: домен, зеркала, включённость, HTML‑страница «сайт отключен».
- Выбор макета по умолчанию и визуальных настроек (см. ниже).

### Компоненты и шаблоны

- Компоненты описывают структуру данных (`fields_json`).
- Для каждого компонента создаются представления (`component_views`) с шаблонами list/single, системными настройками (`system_tpl`) и JSON‑настройками выборки (`query_json`).
- Админка пишет файлы в `templates/component/<keyword>/` и хранит бэкапы.

### Инфоблоки

- Экземпляры компонентов в разделе.
- Указываются шаблон (`view_template`), настройки (`settings_json`) и обёртки (`extra_json`).

### Объекты (контент)

- Создание/редактирование по схеме компонентов.
- Поддерживаются статусы `draft` и `published`.
- Предпросмотр публикуемых объектов доступен только для авторизованного пользователя и использует `preview_token`.

### Макеты и визуальные поля

- Макеты хранятся в `templates/layouts/`.
- Для макета есть отдельный шаблон навигации `<layout>.nav.php`.
- Визуальные поля (`visual_fields`) задают параметры для дизайна.
- Значения хранятся в `sections.extra_json.visual_settings` и наследуются по дереву.

### Пользователи и роли

- Создание/удаление пользователей, смена пароля и роли.

### SQL‑консоль

- Раздел `SQL` позволяет выполнять запросы и хранит историю последних команд.
- Доступен только администраторам.

### Файловый менеджер

- Раздел `Файлы` открывает Tiny File Manager, встроенный в админку.
- Доступен только администраторам, используется авторизация CMS.
- Корень файлового менеджера — корень проекта.
- Входной URL: `/admin.php?action=filemanager`.

### Логи

- Админ‑лог показывает действия пользователей (фильтры по сущности, действию, пользователю).

## Загрузка файлов

- Поля компонентов типа `file` сохраняются в `public_html/files/component/<infoblock_id>/`.
- Файлы визуальных настроек — в `public_html/files/layouts/<layout>/<field_id>/`.
- Проверяются расширения и MIME‑типы (список в `app/admin/AdminHelpers.php`).
