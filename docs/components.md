# Компоненты и представления

Компонент описывает структуру данных и набор шаблонов для вывода контента.

## Структура компонента

- `components.fields_json` — список полей (имя, тип, обязательность, опции).
- `components.views_json` — список имён представлений (синхронизируется с БД).

## Представления компонентов

Каждое представление хранится в `component_views` и содержит:

- `list_tpl` — шаблон списка;
- `single_tpl` — шаблон полного отображения;
- `system_tpl` — системные настройки (PHP‑код).

При сохранении админка формирует файл:

```
templates/component/<keyword>/<view>.php
```

## Шаблоны действий

Для компонента можно задать PHP‑код, который выполняется после создания нового объекта
в админке. Код хранится в файле:

```
templates/component/<keyword>/actions.php
```

Доступные переменные в этом коде: `$message` (ID объекта), `$object`, `$infoblock`, `$component`.

## Системные настройки (`system_tpl`)

Код из `system_tpl` добавляется **в конец** сформированного PHP‑файла, после выбора
между `list` и `single` режимом. Это позволяет:

- объявлять функции и переменные;
- выполнять дополнительную логику;
- готовить данные для шаблона.

### Предлагаемые правила использования

Чтобы сохранить ключевую роль `system_tpl`, но избежать пересечения с настройками инфоблока,
рекомендуется следующий раздел ответственности:

- настройки инфоблока (лимит «выводить по N объектов», HTML до/после) — это конфигурация вывода;
  здесь не размещаются SQL, динамический код или сложная логика.
- `system_tpl` — место для расширенной логики: объявление функций, подготовка данных,
  собственные запросы (включая полную замену выборки объектов) и составление произвольного
  HTML‑вывода, если стандартный список/одиночный режим не подходит.
- Если требуется полностью контролировать выборку объектов, рекомендуется делать это
  прямо в шаблоне (`list`/`single`) через `objects_list()` или собственные запросы,
  а `system_tpl` использовать как контейнер вспомогательных функций и констант.
- Договориться об именовании служебных переменных/функций (например, префикс `sys_`),
  чтобы не пересекаться с переменными шаблона.

## Режимы list/single

Шаблон получает переменные:

- `$isSingle` — режим одного объекта;
- `$objects` — список объектов в режиме list;
- `$object` — первый элемент `$objects` в режиме single.

Полный список переменных и функций — в `docs/templates.md` и `docs/functions-api.md`.
