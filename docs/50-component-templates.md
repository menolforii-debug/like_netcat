# 50. Шаблоны компонента

## Зачем это существует

Документ описывает все сущности, связанные с шаблонами компонента: представления, list/single шаблоны, системные настройки и шаблоны действий.

## Сущности и файлы

### Представление компонента (`component_views`)

Представление — это запись в таблице `component_views`, которая связывает компонент и набор шаблонов.
Она хранит:

- `name` — имя представления (например, `list`, `grid`, `card`).
- `list_tpl` — шаблон списка объектов.
- `single_tpl` — шаблон одного объекта.
- `system_tpl` — системные настройки (PHP‑код для логики и вспомогательных функций).

На основе этих полей формируется файл:

```
templates/component/<component_key>/<view>.php
```

Файл генерируется из админки, содержит секции list/single и помечен как `GENERATED FILE`.

### Шаблон действий компонента (`actions.php`)

Отдельный файл:

```
templates/component/<component_key>/actions.php
```

Он выполняется в админке после создания объекта компонента (в обработчике `object_create`).
Используется для дополнительных действий: логирование, пересчёт связей, синхронизация данных.

## Переменные в шаблонах компонента

Во всех шаблонах компонента доступны следующие переменные:

- `$section` — текущий раздел.
- `$site` — текущий сайт.
- `$infoblock` — инфоблок, который рендерится.
- `$component` — описание компонента.
- `$objects` — массив объектов (для list‑режима).
- `$object` — текущий объект (для single‑режима).
- `$isSingle` — флаг single‑режима.
- `$setFields($obj)` — helper, который разворачивает поля объекта в `$f_*` переменные.
- `$settings` — настройки инфоблока (если переданы в `infoblock` как `settings`).
- `$message_select` — последний SQL‑запрос к объектам (для отладки).
- `$editMode` — признак режима редактирования (если используется).

## Системные настройки (`system_tpl`)

`system_tpl` — это PHP‑код, который хранится в `component_views.system_tpl` и вставляется в конец
генерируемого шаблона представления. Он используется для:

- описания вспомогательных функций;
- подготовки данных, которые нужны всем шаблонам представления;
- диагностических действий (логирование, просмотр запроса);
- изменения системного запроса к объектам.

### Перечень переменных внутри `system_tpl`

Внутри `system_tpl` доступны те же переменные, что и в list/single шаблонах:
`$section`, `$site`, `$infoblock`, `$component`, `$objects`, `$object`, `$isSingle`,
`$setFields`, `$settings`, `$message_select`, `$editMode`.

## Системный запрос: как работает и как его менять

По умолчанию список объектов строится системным запросом, который:

- выбирает записи по `infoblock_id`;
- исключает удалённые записи (`is_deleted = 0`);
- фильтрует по статусу `published` на фронтенде;
- учитывает пагинацию `per_page`.

Менять системный запрос можно через функцию `objects_list()` и фильтры в шаблоне.
Это позволяет подменить `$objects` и тем самым изменить набор данных для рендера.

### Пример: изменить сортировку

```php
<?php
$objects = objects_list([
  'infoblock_id' => (int) $infoblock['id'],
  'order' => 'published_at DESC, id DESC',
]);
?>
<?php foreach ($objects as $obj): ?>
  <?php $setFields($obj); ?>
  <h3><?= htmlspecialchars((string) $f_title, ENT_QUOTES, 'UTF-8') ?></h3>
<?php endforeach; ?>
```

### Пример: добавить фильтр по разделу

```php
<?php
$objects = objects_list([
  'infoblock_id' => (int) $infoblock['id'],
  'section_id' => (int) $section['id'],
  'status' => 'published',
]);
?>
```

### Пример: полный SQL‑запрос

```php
<?php
$objects = objects_list([
  'sql' => 'SELECT * FROM objects WHERE infoblock_id = :id AND status = :status ORDER BY id DESC',
  'params' => ['id' => (int) $infoblock['id'], 'status' => 'published'],
]);
?>
```

После выполнения `objects_list()` можно проверить реальный запрос через `$message_select`.

## Шаблон действий: доступные переменные

В `templates/component/<component_key>/actions.php` доступны основные переменные контекста создания объекта:

- `$message` — ID созданного объекта.
- `$object` — массив данных созданного объекта.
- `$component` — компонент объекта.
- `$infoblock` — инфоблок, в котором создан объект.
- `$data` — очищенные и валидированные данные формы.
- `$status` — статус объекта (`published` или `draft`).
- `$objectRepo` — репозиторий объектов (для дополнительных операций).
