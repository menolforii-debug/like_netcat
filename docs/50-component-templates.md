# 50. Шаблоны компонента

## Зачем это существует

Документ описывает структуру шаблонов компонента: list/single, системные настройки и шаблоны действий.

## Сущности и файлы

### Представление компонента (структура файлов)

Представление — это подпапка внутри компонента:

```
templates/component/<component_key>/<view>/
```

В ней находятся:

- `list.php` — шаблон списка объектов.
- `single.php` — шаблон одного объекта.
- `system.php` — системные настройки выборки (возвращает массив).

### Шаблон действий компонента (`actions.php`)

Отдельный файл:

```
templates/component/<component_key>/actions.php
```

Он выполняется в админке после создания объекта компонента (в обработчике `object_create`).
Используется для дополнительных действий: логирование, пересчёт связей, синхронизация данных.

## Переменные в шаблонах компонента

Во всех шаблонах компонента доступны следующие переменные:

- `$section` — текущий раздел.
- `$site` — текущий сайт.
- `$infoblock` — инфоблок, который рендерится.
- `$component` — описание компонента.
- `$objects` — массив объектов (для list‑режима).
- `$object` — текущий объект (для single‑режима).
- `$isSingle` — флаг single‑режима.
- `$setFields($obj)` — helper, который разворачивает поля объекта в `$f_*` переменные.
- `$settings` — настройки инфоблока (если переданы в `infoblock` как `settings`).
- `$message_select` — последний SQL‑запрос к объектам (для отладки).
- `$editMode` — признак режима редактирования (если используется).
- `$helpers` — массив локальных helper‑функций из `system.php` (ключ => callable).

## Системные настройки (`system.php`)

`system.php` — это PHP‑файл, который **возвращает массив** и выполняется
до системной выборки объектов. Он используется для:

- описания вспомогательных функций;
- подготовки данных, которые нужны всем шаблонам представления;
- диагностических действий (логирование, просмотр запроса);
- управления системным запросом через переменные NetCat.

### Перечень переменных внутри `system.php`

Внутри `system.php` доступны:
`$section`, `$site`, `$infoblock`, `$component`, `$isSingle`.

### Локальные helper‑функции

`system.php` может вернуть ключ `helpers` — массив `['name' => callable]`, который будет доступен
в шаблонах `list.php`/`single.php` как переменная `$helpers`.

```php
<?php
return [
  'helpers' => [
    'formatDate' => static function (string $value): string {
      return date('d.m.Y', strtotime($value));
    },
  ],
];
```

### Переменные, которые управляют системной выборкой

**Ignore‑переменные:**

- `$ignore_sub`
- `$ignore_cc`
- `$ignore_check`
- `$ignore_all`
- `$ignore_limit`

**Query‑переменные:**

- `$query_select`
- `$query_from`
- `$query_join`
- `$query_where`
- `$query_group`
- `$query_having`
- `$query_order`
- `$query_limit`

**Прочее:**

- `$distinct`

Если ключ не задан, считается пустой строкой/0.

## Системный запрос: как работает и как его менять

По умолчанию список объектов строится системным запросом, который:

- выбирает записи по `infoblock_id`;
- исключает удалённые записи (`is_deleted = 0`);
- фильтрует по статусу `published` на фронтенде (если не задан `$ignore_check`);
- учитывает пагинацию `per_page` (если не задан `$ignore_limit`).

Менять системный запрос можно через ключи в массиве, возвращаемом `system.php`.

### Пример `system.php`: изменить сортировку и фильтр

```php
<?php
return [
  'ignore_check' => 1,
  'query_where' => 'a.published_at IS NOT NULL',
  'query_order' => 'a.published_at DESC, a.id DESC',
];
```

### Пример `system.php`: задать лимит вручную

```php
<?php
return [
  'ignore_limit' => 1,
  'query_limit' => '5',
];
```

## objects_list() и системный запрос

`objects_list()` использует тот же механизм сборки SQL, что и системная выборка,
и возвращает массив HTML‑строк (item‑template для каждого объекта).

### Пример: вывести список HTML‑элементов

```php
<?php
$itemsHtml = objects_list([
  'infoblock_id' => (int) $infoblock['id'],
  'query_order' => 'a.published_at DESC, a.id DESC',
]);
?>
<?= implode("", $itemsHtml) ?>
```

После выполнения `objects_list()` можно проверить реальный запрос через `$message_select`.

## Шаблон действий: доступные переменные

В `templates/component/<component_key>/actions.php` доступны основные переменные контекста создания объекта:

- `$message` — ID созданного объекта.
- `$object` — массив данных созданного объекта.
- `$component` — компонент объекта.
- `$infoblock` — инфоблок, в котором создан объект.
- `$data` — очищенные и валидированные данные формы.
- `$status` — статус объекта (`published` или `draft`).
- `$objectRepo` — репозиторий объектов (для дополнительных операций).
