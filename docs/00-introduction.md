# 00. Введение (вход в CMS)

## Зачем это существует

Like Netcat — минималистичная CMS для проектов, где нужен понятный контент‑слой без тяжёлых зависимостей.
Она опирается на SQLite, понятные сущности и PHP‑шаблоны.

## Когда использовать

- Нужен компактный CMS‑слой без внешних сервисов.
- Контент описывается через компоненты и гибко выводится шаблонами.
- Важна простая схема БД и возможность править/мигрировать её SQL‑файлами.

## Когда НЕ использовать

- Требуются сложные разрешения, мультитенантность или REST‑API из коробки.
- Нужен визуальный редактор с сложными WYSIWYG‑вставками.

## Как это работает (кратко)

- Запрос попадает в `public_html/index.php`, где выбирается сайт и раздел.
- Для раздела подбираются инфоблоки и их компоненты.
- Компоненты отдают HTML через шаблоны (`templates/component/...`).
- Макет (`templates/layouts/...`) оборачивает результат.

## Примеры

### Пример: создание минимальной структуры

```php
// Псевдокод: создать раздел, компонент и инфоблок
$sectionId = 1; // сайт/раздел
$componentId = 3; // компонент
$infoblockId = $infoblockRepo->create([
  'site_id' => 1,
  'section_id' => $sectionId,
  'component_id' => $componentId,
  'name' => 'Новости',
  'view_template' => 'list',
  'key' => 'news',
  'per_page' => 10,
  'extra' => ['before_html' => '<h2>Новости</h2>'],
]);
```

### Типовой сценарий

- Создать компонент “Новости” с полями `title`, `body`.
- Создать view `list` и `single`.
- Создать инфоблок в разделе и заполнить объектами.

### Как делать НЕ надо

```php
// НЕ надо обращаться к БД напрямую в шаблоне без фильтров
$rows = DB::fetchAll("SELECT * FROM objects"); // слишком широко и медленно
```

## Частые ошибки

- Путают уровни: инфоблоки не заменяют компоненты.
- Хранят бизнес‑логику в макетах вместо компонентов.
