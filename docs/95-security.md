# Безопасность

О чём документ: встроенные меры защиты и чек‑лист для разработчика.
Когда читать: перед деплоем и при написании шаблонов/админ‑действий.
Кому полезно: разработчикам и инженерам эксплуатации.
Связанные документы: `docs/50-system-php-contract.md`, `docs/80-admin-handbook.md`.

## Что уже защищено в коде
- **Защитная проверка рантайма**: `assert_runtime()` ограничивает запуск админских скриптов вне рантайма `admin`.
- **Пути шаблонов и врезок**: проверка регулярным выражением + `realpath` (защита от обхода директорий).
- **Действия админки**: имя `action` проверяется регулярным выражением, путь — через `realpath` и базовую директорию.
- **`CSRF`**: обязательная проверка для `POST`‑действий (кроме `login`).
- **Предпросмотр**: требует авторизацию и токен сессии.
- **Загрузки**: фильтрация по расширениям и `MIME`‑типам; хранение в `public_html/files/...`.
- **Удаление файлов**: `rmTree()` ограничивает удаление только внутри `public_html/files`.
- **Сессии**: `httponly`, `samesite`, `secure` (если `HTTPS`).

## Ответственность разработчика
- Экранировать вывод пользовательских данных (`htmlspecialchars`).
- Не вставлять непроверенный `SQL` в `system.php` (`query_*` вставляются как есть).
- Не доверять данным из `data_json` без валидации.
- Не использовать динамическое `require` без проверки пути.

## Чек‑лист перед выкладкой
- [ ] Проверить права на `var/`, `templates/`, `public_html/files/`.
- [ ] Отключить/ограничить отладочный вывод при необходимости.
- [ ] Убедиться, что `preview_token` используется только в админских сценариях.
- [ ] Убедиться, что формы в админке содержат `csrf_token_field()`.
- [ ] Проверить, что шаблоны экранируют данные.

## Замечание по `display_errors`
В `public_html/index.php` включён `display_errors=1`. Это стоит учитывать при публикации.
