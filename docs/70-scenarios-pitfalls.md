# 70. Типовые сценарии и грабли

## Зачем это существует

Сводка частых задач и проблем, которые встречаются при работе с CMS.

## Когда использовать

- Нужно быстро решить типовую задачу.
- Возникла ошибка, и не ясно, где искать причину.

## Когда НЕ использовать

- Для понимания архитектуры — см. `docs/00-introduction.md`.

## Как это работает (кратко)

Сценарии построены вокруг типовых задач: добавление контента, отладка выборок, правка шаблонов.

## Примеры

### Сценарий: ограничить вывод 10 объектов

```php
// В админке задайте per_page = 10 для инфоблока
// или в шаблоне используйте фильтр:
$items = objects_list(['infoblock_id' => 10, 'status' => 'published', 'limit' => 10]);
```

### Сценарий: использовать $f_* переменные в list

```php
<?php foreach ($objects as $obj): ?>
  <?php $setFields($obj); ?>
  <h3><?= htmlspecialchars((string) $f_title, ENT_QUOTES, 'UTF-8') ?></h3>
<?php endforeach; ?>
```

### Как делать НЕ надо

```php
// НЕ вызывайте resize_image() на каждом рендере страницы
$img = resize_image($path, 800, 600); // дорого для рендера
```

## Частые ошибки

- Включают тяжёлую логику в шаблон вместо вынесения в действия/скрипты.
- Забывают, что `per_page` ограничивает выборку, но не делает пагинацию.
