# 50. Шаблоны и макеты

## Зачем это существует

Шаблоны компонентов отвечают за HTML инфоблоков, а макеты — за общий каркас страницы.

## Когда использовать

- Когда нужно изменить вывод конкретного компонента — правьте шаблон.
- Когда нужно изменить общий HTML страницы — правьте макет.

## Когда НЕ использовать

- Не вставляйте бизнес‑логику в макеты: для этого есть компоненты.

## Как это работает (кратко)

- Шаблон компонента получает `$section`, `$site`, `$infoblock`, `$component`, `$objects`.
- В single‑режиме доступен `$object`.
- Макет получает `$ctx` (контекст страницы) и выводит `$core['infoblocks_html']`.

## Примеры

### Пример: list‑шаблон

```php
<?php foreach ($objects as $obj): ?>
  <?php $setFields($obj); ?>
  <article>
    <h2><?= htmlspecialchars((string) $f_title, ENT_QUOTES, 'UTF-8') ?></h2>
  </article>
<?php endforeach; ?>
```

### Пример: макет

```php
<?= Layout::renderDocumentStart($ctx['title'] ?? '', $ctx['meta'] ?? []) ?>
<main>
  <?= $core['infoblocks_html'] ?? '' ?>
</main>
<?= Layout::renderDocumentEnd() ?>
```

### Типовой сценарий

- В list‑шаблоне использовать `$setFields($obj)` и `$f_*` переменные.
- В макете вызвать `Layout::renderSectionHeader()` для вывода заголовка раздела.

### Как делать НЕ надо

```php
// НЕ заменяйте $core['infoblocks_html'] вручную в макете
$core['infoblocks_html'] = '';
```

## Частые ошибки

- Путают контекст макета и шаблона компонента.
